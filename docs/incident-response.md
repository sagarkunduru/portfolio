# Incident Response Model

```text
Detect → Triage → Stabilize → Diagnose → Recover → Validate → Learn
```

## Priorities
1. Protect users and data.
2. Reduce blast radius.
3. Establish a reliable timeline.
4. Use metrics, logs and deployment history to test hypotheses.
5. Make the smallest safe recovery change.
6. Verify recovery with service-level signals.
7. Document cause, contributing factors and follow-up actions.

The objective is not merely to clear an alert; it is to restore a healthy service safely and leave the system easier to operate afterward.
